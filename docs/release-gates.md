## Certificate review before a tagged research release

1. Pin the statement/table schema, checker source and resource limits. Independently inspect that the claim being checked matches the intended task.
2. For proof certificates, retain separate results for statement binding, valid refutation, and a satisfying model of the original premises. Reject theorem replacement, added premises, invented resolvents, forward references, incomplete refutations and inconsistent witnesses.
3. Exercise the standalone proof verifier with an externally pinned statement hash. A claimant-controlled statement and matching hash alone do not establish authenticity or relevance.
4. For diagnosis, review every informative alternative in the minimax recurrence, not only the chosen strategy. Check an attaining decision tree independently and enforce the experiment cap separately from general tool cost.
5. Verify that elimination witnesses name actual observations and exclude every competing world. A guessed current-world ID, fabricated query or incomplete witness set must fail strict success.
6. Review malformed, duplicate, oversized and adversarial certificates, and compare small cases against independent semantic implementations. Report the environment and the remaining trusted computing base.
7. Export representative certificates and their public statements for independent review. Keep the private world state and scored-agent access restrictions intact.
8. For finite games, check every legal action and observation branch, strict rank decrease, positive costs and an attaining raw-transition strategy. Bind policy mode, root, root value and node count to the actual checked artifact.
9. Kernel-check equality of the full arena with an independently rendered expected literal. A matching JSON printout alone cannot establish that the theorem concerns that arena.
10. Pin the expected theorem-root inventory for export replay. Reject absent roots, unexpected axioms and deliberately malformed proofs with actual type-error diagnostics, rather than counting process crashes as successful negative controls.

These checks are review obligations, not a claim that exhaustive tests establish correctness for every possible parser/runtime condition. Extending the formal assurance to the full Python-facing implementation would require a verified interface/refinement argument, including parsing, bounds and artifact translation. The current Lean theorem and exact release-instance round-trips cover only their published scope.

## Before a comparative benchmark paper

1. Freeze source, tasks, skill hashes, inference budgets and statistical plan.
2. Obtain independent human review of task interpretation, solvability and alternative answers.
3. Test real models with provider/version/prompt/usage records and externally isolated evaluator hosts.
4. Create many independently authored structural templates; new seeds alone are insufficient.
5. Reserve a private future pool after difficulty calibration. Keep graders, seeds and task state outside agent filesystems.
6. Run matched-information and matched-token ablations, including genuinely static evidence, active sensing and causal masking.
7. Analyze correlations with established benchmarks and failure modes to establish incremental measurement value.
8. Publish complete permitted traces, costs, errors and confidence intervals; disclose adaptive selection and excluded runs.
9. Have another group reproduce the findings.

Record `twin_kind` and report `causal_parameter`, `wall_y_translation`, `theorem_polarity`, `diagnostic_state`, `demand_trajectory`, `target_horizontal_translation`, `gate_lane`, `surface_friction`, and `sensor_corruption` separately. Theorem binding and categorical state identification are valuable but do not establish physical causal inference. Keep prior releases' task rosters comparable before contrasting headline numbers; adding a challenge profile changes the average being measured.

Any exploratory model run must disclose isolation limits, missing deployment metadata and the opportunity for contamination. A shared-host trial or a model-assisted certificate is useful development evidence, but it is not equivalent to an independently isolated leaderboard submission. A successful hard-setting run is also evidence against declaring that setting universally difficult.

## Difficulty calibration after the shortcut audit

The original vending and robotics generators admit valid fixed controls. Retain those results and avoid claiming that all available feedback is necessary. The barrier profile certifies a need for some hidden-geometry observation, but has an efficient constructive solver. The new `vending_adaptive` challenge now supplies feasible hidden demand sequences, irreversible inventory decisions and complete certificates: the audited profiles are adaptively solvable, while no fixed observation-independent action sequence guarantees success. The independent no-experiment restriction is also losing despite retaining ordinary operational feedback. Direct assays remain valid alternatives to calibrated forecasts.

The fresh-context pilot succeeded on all six sampled hard-setting tasks,
including all three adaptive-market splits. This supports interface usability
and alternative-strategy acceptance. It is evidence against describing these
settings as universally difficult. Future calibration should vary independent
mechanisms and information/computation budgets, measure a difficulty curve, and
freeze a new held-out pool after authoring. Do not reject robust valid policies
solely because they use fewer tools.

## Before a robotics improvement claim

The release now has controlled 2D camera observations, bounded fixed-pattern
noise, affine calibration, occlusion, and an authored contact transition model.
The next stage is a licensed external physics-simulator adapter with realistic
sensors and contact dynamics, independently held-out environments/objects, and
an explicit conformance audit of its abstraction. Compare equal-data/equal-compute
learned controllers and test executed outcomes. Real-world transfer requires a
separate robot evaluation. See [The detailed research agenda](research-agenda-v0.5.md)
and the preregisterable protocol in `configs/vision-study-v0.5.json`.

## Before a stronger scientific claim

Provide the comparative evidence above and delimit the proposed contribution against code infilling, SkillsBench, ARC, Vending-Bench, Axiom's checked-proof workflow, VERINA, miniF2F and exact query learning. High dimension, long traces, proof length, unit-test count and a large generated dataset do not establish novelty or intelligence. An exact finite query optimum establishes a resource property of the permitted experiments; it does not establish language-model difficulty. A failure deliberately made unanswerable belongs in the calibration track.
