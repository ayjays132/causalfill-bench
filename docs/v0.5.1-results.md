# CausalFill-Bench v0.5.1: verified release results

**Signal Repair extends the benchmark to 15 task configurations across nine
conceptual domains.** The new track combines one episode-wide corruption cap,
overlapping action regions, exact finite sensing-and-action costs, irreversible
execution, and observed exclusion witnesses. A coordinated original visual
identity, task cards, evidence cards and report accompany the implementation.

The consolidated [verification record](../reports/v051/release-verification.json)
rechecks source binding, exact suite coverage, stored trace chains, formal source
and export hashes, intended negative-control outcomes and result denominators.
Its passing status means these development gates completed. It is not a
scientific novelty, physical-safety or frontier-model-hardness certification.

## Independent finite stress audit

The independent oracle expands each fixed world with each whole-episode fault
subset. It filters those explicit atoms by observed outcomes and searches
remaining queries. It does not reuse the engine's mismatch-state update or
bitmask layers. The complete tiny corpus contains all 1,536 combinations of
two-world/two-query truth tables, two action success sets, corruption caps
0–2 and two fixed cost profiles; action and identification objectives produce
3,072 comparisons. Another 256 random models contribute 512 comparisons.

The certificate checker accepted 4,234 artifacts in the audit, including
analytic and metamorphic variants. A separate policy replay accepted 1,644
finite solutions. Resource counts, represented states and repeated checks are
correlated engineering measurements, not independent benchmark problems.

The 1,280 forged-certificate controls comprise 256 each of stale digest,
incorrect optimum, duplicate state, missing root, and a claimant changing the
requested objective. Additional unit tests cover dropped alternatives, malformed
types, false witnesses, zero-cost bypasses, unreachable branches, evidence
identity and declared resource caps.

The runtime audit executes every world and fault subset of size at most `k`
for three seeds across all nine profiles. Every reference run commits through
the actual Session interface and submits real witnesses. Its maximum observed
cost attains the certified bound in every one of the 27 profiles. This checks
one certified policy over all cases in those models; it does not enumerate
every arbitrary policy or prove the runtime equivalent to Lean.

Source: [stress result and profiles](../reports/robust-stress-v0.5.1/result.json).
The initial passing stress run is retained separately. Review then identified
a possible accumulation of large cached certificates; the cache was reduced
from 128 entries to eight and the full audit was rerun on the frozen source.

## Outcome and justification are different measurements

| Restricted scripted policy | Episodes | Actual operation succeeds | Robustly justified at commitment | Strict success |
|---|---:|---:|---:|---:|
| Plan as though no sensor can be corrupt | 90 | 79 | 0 | 0 |
| Query every sensor before acting | 90 | 40 | 40 | 40 |

The first control often gets the selected-world outcome right but lacks the
required evidence under the published cap. Even a clean episode does not tell
the solver that all sensors were clean. The second spends resources on
unnecessary sensing and can leave the final action unaffordable. Some profiles
do allow full sensing, so those cases remain valid successes. These policies
are deliberately restricted diagnostics and must not be labeled AI results.
Source: [180-episode ablation](../reports/v051/robust-ablation/summary.json).

## Fresh-context assistant pilot

The evaluator froze the core and committed six fresh cases before delivering
their public contracts. The assistant received no author conversation, grader,
private seed or reference-policy source. It wrote its own exact minimax planner
from the public truth tables, preserved mismatch counts and remaining probes,
and independently checked its final witnesses. The evaluator's private results
confirm six strict successes.

| Case | Profile | Probes | Operational cost / cap | Worlds remaining | Assigned / observed faults |
|---|---|---:|---:|---:|---:|
| 1 | Train 3 | 7 | 8 / 8 | 1 | 1 / 1 |
| 2 | Dev 2 | 6 | 7 / 7 | 1 | 1 / 1 |
| 3 | Dev 3 | 7 | 8 / 8 | 1 | 1 / 1 |
| 4 | Transfer 1 | 2 | 3 / 3 | 6 | 1 / 1 |
| 5 | Transfer 2 | 0 | 5 / 5 | 8 | 1 / 0 |
| 6 | Transfer 3 | 7 | 9 / 11 | 1 | 2 / 1 |

The last case was assigned two faulty sensors but encountered one; it is not
a measured two-observed-fault pilot success. The complete finite runtime audit
does cover all fault subsets in its selected profiles. Case 4 demonstrates
decision sufficiency without identity recovery. Case 5 demonstrates a valid
universal bypass. Both are accepted because the task allows them.

This pilot used a public JSON mailbox on a shared host. Separation was enforced
by solver instructions, not an OS sandbox or a filesystem-access audit. Full
model inference settings, token accounting and inference timing were not
available. Session wall time includes host waiting. Six related generated
cases, solved in one assistant context, do not support a broad success-rate,
human-calibration or frontier-hardness claim. The result indicates that these
released mechanisms remain tractable for this tool-using assistant.

The preceding HTTP attempt delivered no contracts: all endpoints refused
connections from the solver surface. It is preserved as an infrastructure
block, excluded from agent reasoning scores. Source:
[completed mailbox pilot](../reports/public-mailbox-pilot-v0.5.1/manifest.json)
and [transport record](../reports/public-pilot-v0.5.1/infrastructure-status.json).

## What the formal result establishes

Fourteen generic theorem roots cover exact mismatch accounting, equivalence
with honest/flip realizations, saturated count updates, preservation of the
true world within the declared cap, permanent exclusion, occurrence-supported
witnesses and safe action. A separate audit binds all fourteen expected types.
Only the allowed standard axioms `propext`, `Classical.choice` and `Quot.sound`
appear; there are no unsafe exported declarations.

Five incorrect semantic claims, an injected custom axiom and an omitted root
are rejected. Two weakened but well-typed replacement theorems compile on their
own and fail the untouched expected-type audit. Six checker configurations
accept the valid export and reject the deliberately corrupted proof term with
the intended type-failure diagnostics.

The proof does not formalize the Python optimizer's Bellman costs, generic
Python-to-Lean equivalence, sensor hardware, real-world action dynamics or the
meaning of a physical fault cap. Those boundaries are explicit. The normal
Lean CLI failed to locate its application on this host, so the unchanged public
C ABI host initialized the official 4.35.0 toolchain at trust level zero.
No proof checker or OS control was replaced. A first harness fixture failure
and its repair remain preserved. See [full formal record](../formal/verification-v051-fault/README.md).

## Reproduce the completed gates

Use fresh output paths:

```bash
python tools/run_unit_gate_v051.py --output private-runs/units
python -m causalfill suite --output private-runs/suite \
  --splits train dev transfer --difficulties 1 2 3 --count 5 \
  --policies evidence blind abstain
python tools/stress_robust_v051.py --cases 256 --runtime-seeds 3 \
  --output private-runs/robust
python tools/stress_robust_ablation_v051.py --seeds 5 \
  --output private-runs/ablations
```

Formal reproduction commands are in the linked formal record. Rendering the
optional card/PDF assets uses development tools such as Pillow, Inkscape and
ReportLab. The prospective [evaluation and robotics plan](evaluation-plan-v0.5.1.md)
specifies the next tests needed for stronger claims; none is presented as an
experiment already completed.
