# Signal Repair: the live robust-sensing task

`robust_sensing` belongs to the diagnosis/decision domain. It asks for a missing
action and a proof-carrying explanation assembled from real observations. It
requires the action to be executed through the tool interface before accepting
the completion. The environment is a finite symbolic controller, not a
physical robot or an unrestricted desktop.

## What is public and what is private

The file `/formal/robust-sensing.json` lists every candidate world, each sensor's
truthful response, each action's successful worlds, costs, the shared corruption
cap, the operational budget and a SHA-256 problem digest. World labels, sensor
labels, sensor polarities, and action order are permuted by the generator.

The evaluator privately selects a fixed world and a set of faulty probes. A
faulty probe flips its truthful response if used. No more than `k` distinct
probes are faulty; the clean twin has none and the assigned-fault twin has `k`.
Unused faulty probes do not count as observed corruptions. The public contract,
world and nuisance randomization are identical across these paired reset cases.

The certificate machinery covers every world and legal fault placement. A
fixed complete subset representation suffices for runtime replay: every path
generated by an adaptive bounded adversary induces a subset of flipped probe
IDs along that path. The policy verifier additionally explores honest/flip
branches under each fixed world directly.

## Tools and cost accounting

Each listed query has one named tool such as `probe_q03` with empty arguments.
It returns its query ID, observed bit, and number of remaining probes. It never
reveals the truthful bit, whether that answer was corrupt, or the selected
world. Reusing a probe is rejected without changing the task state.

Each action likewise has a named tool such as `commit_a02` with empty arguments.
It captures the current observation history and commits irreversibly. No probe
or second action is accepted afterward. The response acknowledges commitment
without revealing the private grade.

The operational cap is the checked minimum worst-case total of accepted probe
costs plus one terminal action cost. The Session separately allows two setup
credits for a contract read and an optional explanation read. Unused setup
credits cannot enlarge the operational cap. Rejected Session calls can still
consume Session cost; over-cap task actions never mutate the task state.

Planning computation and final submission are outside this synthetic cost.
Consequently, optimal tool cost does not mean optimal wall time, memory, tokens,
monetary cost, or practical robot performance.

## Required fill

```json
{
  "problem_sha256": "digest copied from this episode's public contract",
  "action": "a02",
  "exclusions": [
    {"world": "w00", "conflicts": ["q01", "q03"]}
  ]
}
```

This illustrates the format only; it is not a valid answer to a particular
episode. Every world outside the committed action's success set must appear
exactly once. It needs at least `k+1` distinct probe IDs whose accepted
pre-commit observations contradict that world's truthful table. Each probe
is one-use, so these IDs identify distinct recorded occurrences. The outer
Session submission also carries observed event IDs, confidence and the
abstention flag. A digest binds to a problem; it is not a signature or a source
of trust when provided solely by a claimant.

Strict success requires actual selected-world success, robust justification in
all compatible worlds, valid complete witnesses, actual commitment, and
compliance with the operational cap. An empty compatible-world set is never
accepted as vacuous justification. A common successful bypass needs no
excluded-world witnesses. The runtime permits more than the minimum number
of distinct contradictions; the core canonical witness helper emits exactly
`k+1`.

## A small worked example

Suppose two worlds predict three separate probes as `000` and `111`. The shared
fault cap is one. After observations `0,1`, both worlds remain possible: each
requires one corrupted reading. A third observation of `1` leaves mismatch
counts two and one. The `000` world is now excluded. Cite the two distinct
probes that returned `1` to justify the action for world `111`.

The evidence obligation prevents treating the first reading as certain or
reusing one contradictory observation twice. It also permits early stopping:
if the first two observations agree, the opposing world already requires two
errors. Repeating a single sensor is forbidden; three sensors with the same
truth table are distinct one-use experiments.

## Implemented structural profiles

| Split and level | Public finite structure | Shared cap | Certified worst-case operational cost |
|---|---|---:|---:|
| Train 1 | One bit, three repeated-code sensors | 1 | 4 |
| Train 2 | Two bits, six repeated-code sensors | 1 | 6 |
| Train 3 | Three bits, nine repeated-code sensors | 1 | 8 |
| Dev 1 | One-bit repetition code | 1 | 4 |
| Dev 2 | Eight worlds, six punctured-simplex sensors | 1 | 7 |
| Dev 3 | Sixteen worlds, seven Hamming-code sensors | 1 | 8 |
| Transfer 1 | Eight worlds, seven sensors, overlapping actions | 1 | 3 |
| Transfer 2 | Weighted sensors/actions and a universal bypass | 1 | Depends on public costs; 5–6 in the three audited profiles |
| Transfer 3 | Eight worlds, ten extended-simplex sensors | 2 | 11 |

Costs include the terminal action. The two-corruption profile can stop after
nine probes in the worst case and pays two units for the terminal action. The
first transfer profile can decide after two probes without uniquely identifying
the world. Repetition, Hamming/simplex codes, search with lies and decision
regions are established prior art; these are original benchmark fixtures using
those ideas. Profile labels are not independently authored mechanisms or a
human difficulty calibration. Source: [the complete finite/runtime audit](../reports/robust-stress-v0.5.1/result.json).

## Reproduction and boundaries

```bash
python -m causalfill demo --family robust_sensing --split transfer --difficulty 3
python -m unittest tests.test_robust_decisions tests.test_robust_sensing -v
python tools/stress_robust_v051.py --cases 256 --runtime-seeds 3 --output private-runs/robust
```

The reference policy reads the same contract and tool responses through the
public callback. It is a deliberately strong task-aware scripted controller,
not a learned-model result. The public-contract certificate cache retains at
most eight entries; selected worlds and hidden fault sets are never cached.
The resource caps of the finite engine bound its supported problem class.

The generic Lean theorem scope and the unproved Python/physical boundaries are
given in [the formal record](../formal/verification-v051-fault/README.md).
[Research positioning](robust-research.md) explains prior art and the proposed
human, model, mechanism-holdout and robotics experiments. Actual difficulty
must be measured after freezing the evaluator and solver conditions.
