## 1. What changed

The new `vending_adaptive` configuration adds irreversible procurement decisions
under hidden demand. Its two, three or four rounds are intentionally small enough
to expose a complete finite operational model. An agent recovers four masked
terms, obtains evidence, orders stock and meets service and cash goals. The
scorer accepts successful alternatives; no named sensor or reference history is
required. The original vending task remains available with its original rules.

A new finite-belief-game library computes and separately checks complete
minimum-worst-case-cost certificates. A distinct strategy checker replays raw
state transitions from every initial world. The formal development proves
generic lower and upper bounds and exactness in Lean. Concrete arena equality
proofs strengthen the link between an intended finite artifact and the object
covered by its theorem.

This is a useful extension of the benchmark's verification contract. Classical
belief-space planning, minimax recurrences, weighted set cover and proof checking
remain prior art. Neither a new general planning algorithm nor frontier-model
hardness has been established.

## 2. Exact operational cost

These values are minimum worst-case cumulative action costs for guaranteed
success over the declared complete candidate-world table. They are not currency,
tokens, computation time or total Session cost.

| Split | Two rounds | Three rounds | Four rounds |
|---|---:|---:|---:|
| Train | 8 | 12 | 16 |
| Dev | 9 | 13 | 17 |
| Transfer | 8 | 13 | 17 |

All audited profiles lack a guaranteed-success policy in each restricted class:

| Class | Restriction |
|---|---|
| `no_observe` | Remove explicit paid experiment actions; retain ordinary operational feedback. |
| `open_loop` | Permit the actions but require a common action sequence independent of every observation. |
| `open_loop_no_observe` | Apply both restrictions. |

The null value means no finite guaranteed-success policy in that class. It does
not mean zero success probability on every individual world. The finite model
includes calibration, sampling, orders and settlement. Setup reads, static quote
calls and final masked-term reconstruction are outside this operational bound.

The complete certificate checks all relevant action alternatives, so it supplies
a lower bound. Raw-world replay supplies an attaining upper bound. Strictly
decreasing ranks make the finite reasoning well-founded. A single successful
policy, on its own, would establish only an upper bound.

The runtime checks include 334,464 stuttering-tool checks, 1,533,240 selected
invalid-action checks, 48,636 equivalent-history extra-response comparisons and
74,667 equivalent-transition complete-response comparisons. Cash and inventory
are independently reconstructed. Over-budget orders must be atomic. Status,
ledger, quote, error, invoice and settlement responses are inspected for extra
information outside the modeled observations.

Coverage is deliberately stated as a finite audit: it does not enumerate every
possible runtime history or every possible malformed byte string. Complete
syntactic-policy enumeration can contain behaviorally equivalent policies on
unreachable histories. The assertion, state, edge, certificate and episode
counts must not be added together into an intelligence score.

## 4. Formal assurance and statement binding

The official Lean 4.35.0 runtime checked the sources at trust level zero through
its documented C embedding API. The exact downloaded toolchain hash, compiler
host source, input hashes and logs are retained. No syscall interception or
modified proof kernel was used. The embedding was necessary because the CLI
could not locate its application path in this execution environment.

The new development has 21 generic theorem roots: indistinguishability,
finite observation-class capacity, finite ranked strategy lower bounds,
impossibility, attaining upper bounds and exact cost. The observation-class
statement allows different worlds to share a valid completion; distinct world
labels alone do not force distinct answers.

Concrete assurance covers four policy-mode arenas of **one two-round, four-world
market**, with 448 raw states and 732 raw edges. Adaptive, no-observe, open-loop
and combined restriction produce 326, 63, 40 and 10 belief nodes respectively.
The adaptive theorem certifies cost 8; the restricted modes certify that no
finite strategy guarantees success.

Four additional whole-arena equality proofs bind those imported arenas to
independently rendered expected literals. Each bound profile combines equality
with the intended shape and cost/impossibility property. This closes a concrete
statement-binding gap: an exporter can print expected JSON while the theorem
mentions a different mathematical object. A deliberately altered arena with an
unchanged JSON echo was rejected by the equality gate.

All **29 new roots** were exported to a 6,638,404-byte NDJSON artifact and accepted
by these configurations:

| Configuration | Role |
|---|---|
| `leanchecker` | Lean kernel export replay. |
| `leanchecker-paranoid` | Hardened Lean checker configuration. |
| `lean4lean` | External checker implementation. |
| `nanoda` | External checker implementation with strict axiom whitelist. |
| `con-ron` | External checker implementation. |
| `con-leche` | External checker implementation. |

Each also rejected the deliberately ill-typed proof with an actual type-error
diagnostic. These are six configurations including four external implementations,
not six wholly unrelated software stacks. Exported axioms were exactly
`propext` and `Quot.sound`. The root-inventory check rejects missing theorem
names; the export audit rejects custom axioms and unsafe declarations.

The earlier 865-step and 6,018-step resolution certificates were separately
rechecked in this release. They are not included in the new 29-root independent
export. No custom axiom, admitted proof or `native_decide` shortcut is used.

The remaining trusted components include Python parsing, the raw-game-to-belief
projection, expected-data construction, build machinery and the simulator/model
correspondence. The concrete equality theorem does not prove those components
correct for every input. The Lake paranoid build sandbox was not run. See
[formal documentation](formal-information.md) for exact sources and commands.

## 5. Repairs and negative-control provenance

Independent review found that a manifest could relabel an adaptive result as
open-loop while preserving its cost. The binding verifier now compares policy
mode, root, node count and root value against the actual rechecked certificate.
All four corresponding metadata mutations are rejected. This was an evidence
binding defect; the original certificate and core evaluator were unchanged.

The formal mutation campaign passed ten targeted negative controls, including
wrong lower/upper values, bad ranks, empty branches, omitted alternatives,
rerouted children, custom axioms, absent/duplicate roots and the misleading JSON
echo. A separate fresh-context skill reviewer rejected a planted open-loop-cost-8
claim and independently found no all-success fixed sequence in the raw graph.

An earlier export-negative-control harness picked an expression with a free
universe parameter. All checkers rejected it, but the strict gate correctly did
not credit this as the intended type-mismatch test. The corrected harness selects
the closed `Sort 0`; the final six negative controls all show the intended
diagnostics. The baseline logs and exact old harness are preserved. Failed
large-proof concurrency and unavailable HTTP/isolation attempts are likewise
retained as infrastructure history, not counted as successful evaluations.

## 6. Fresh-context public-interface assistant pilot

The solver received only public-interface instructions in a fresh context, a
committed hidden episode roster and a generic mailbox client. No evaluator code,
private seed, reference policy or authoring conversation was supplied in its
prompt. Six tasks were completed with one submission each and zero invalid calls.

| Task | Split / level | Strict result | Total tool cost |
|---|---|---|---:|
| Adaptive market | Train / 3 | Success | 26 / 28 |
| Adaptive market | Dev / 3 | Success | 26 / 28 |
| Adaptive market | Transfer / 3 | Success | 26 / 28 |
| Barrier robotics | Transfer / 3 | Success | 19 / 40 |
| Diagnosis | Transfer / 3 | Success | 6 / 7 |
| Propositional proof | Transfer / 3 | Success | 4 / 20 |

The market solver used direct assays in every round, not the reference's
forecast/calibration approach. Its operational cost was 20 in each market, plus
6 setup/static units, compared with profile minimax costs of 16, 17 and 17. These
are post-hoc cost comparisons, not pointwise optimal-regret claims. Success and
efficiency expose different behavior.

The proof solver wrote its own proof-producing search and submitted a checked
865-step resolution derivation with a satisfying premise model. Its own search
and replay artifacts are retained. The robot solver performed numeric affine
camera calibration and selected a valid sensed route. The diagnosis solver
supplied observations excluding all 31 competing worlds.

This is an exploratory shared-host pilot. Public-only access was instructed and
the retained scripts were inspected, but OS-enforced isolation and access
attestation were unavailable. An attempted local HTTP connection was unreachable
from the solver surface before any task observations; those attempts are excluded
as infrastructure failures. A public JSON filesystem mailbox carried the actual
pilot. Exact serving-model snapshot and token/compute telemetry were unavailable.
Do not present 6/6 as a certified leaderboard score or an estimated population
accuracy. It provides no basis to call these profiles frontier-hard.

## 7. Reproduce and extend

From the source root, use a new output path for each rerun:

```bash
python -m unittest discover -s tests -v
python -m causalfill suite --output private-runs/v04-controls \
  --splits train dev transfer --difficulties 1 2 3 --count 5 \
  --policies evidence blind abstain
python tools/stress_belief_v04.py --cases 60 \
  --output private-runs/v04-belief.json
python tools/stress_adaptive_v04.py --seeds 3 \
  --output private-runs/v04-runtime.json
python tools/stress_protocol.py --output private-runs/v04-protocol.json
```

The core requires Python 3.10+ and no third-party runtime dependencies; this
release was exercised on Linux/Python 3.12. Lean is optional and separately
installed. [Formal README](../formal/README.md) contains the pinned-toolchain,
source, binding, export and independent-checker commands. The versioned release
assembler reads the shipped source-bound evidence without rerunning these
campaigns:

```bash
python tools/build_release_verification_v04.py
```

Useful next scientific work is independent task construction, an externally
isolated multi-model study with exact deployment and compute metadata, matched
information/cost ablations and a private structural holdout. For robotics, add
actual camera imagery and a licensed dynamics simulator, then test perception
and action under controlled interventions. Physical transfer needs a separate
robot experiment. A benchmark can expose failures; training benefit is a further
causal hypothesis requiring an independent experiment.

The source is prepared for GitHub review. No external GitHub repository or
leaderboard was published during this build. See [Release gates](release-gates.md)
for the criteria before broader scientific claims.
